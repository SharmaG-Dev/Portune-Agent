# Tunnexo Agent

**Complete setup guide (Hinglish): [macOS, Linux and Windows instructions](TUNNEXO_SETUP.md)** — installation, commands, configuration, updates and troubleshooting.

Official website: [tunnexo.live](https://tunnexo.live). Public tunnel URLs use `https://<subdomain>.tunnexo.live` when connected to the configured production server.

Tunnexo Agent connects an application running on your computer to the Tunnexo tunnel network. It forwards requests from a server-assigned public URL to your local application and sends its responses back to the visitor.

Use it to share a local web application, demonstrate work in progress, or receive webhooks while developing. Your application and the agent must stay running for requests to reach your computer.

## What it does

- Connects to a Tunnexo server using your agent token.
- Requests a public tunnel with a subdomain generated by the server.
- Forwards HTTP requests to the local URL you choose.
- Displays the public URL and request activity in your terminal.
- Automatically names the agent using its local IP and your configured name prefix.

## Use the downloaded agent

### 1. Extract your download

Extract the ZIP or TAR.GZ archive into a folder. The executable is `tunnexo` on macOS/Linux or `tunnexo.exe` on Windows. Open a terminal in that folder.

### 2. Authentication status

The agent has built-in defaults:

- Backend: `https://tunnexo.live/tunnel`.
- Agent name prefix: `tunnexo`.
- Public tunnel URLs: `https://<subdomain>.tunnexo.live`, assigned by the server.

Users do not need to configure a server URL or name prefix. A `.env` file is optional.

**Automatic token registration is not implemented yet:** backend registration API details are needed. Until that integration is available, a valid server-issued token is still required. Set it in your current terminal:

macOS/Linux:

```sh
export TUNNEXO_AGENT_TOKEN='your-server-issued-token'
```

Windows PowerShell:

```powershell
$env:TUNNEXO_AGENT_TOKEN = 'your-server-issued-token'
```

Alternatively, put `TUNNEXO_AGENT_TOKEN=your-server-issued-token` in an optional `.env` file in the folder where you run the command. Keep tokens private; shell commands containing tokens may be saved in shell history.

Advanced users can override `TUNNEXO_SERVER_URL` and `TUNNEXO_AGENT_NAME_PREFIX`. For each setting, new-name environment values take precedence over new-name `.env` values, followed by legacy `PORTUNE_*` environment and file values. Empty server/prefix values select built-in defaults; an empty token produces an authentication setup error.

### 3. Start your tunnel

Make sure your local application is running. Replace `http://localhost:4000` below with its address.

**macOS / Linux**

```sh
chmod +x ./tunnexo
./tunnexo agent --target http://localhost:4000
```

**Windows PowerShell**

```powershell
.\tunnexo.exe agent --target http://localhost:4000
```

After authentication and tunnel creation, the terminal displays the public URL returned by the server. Open or share that URL to access your application. You do not need to choose a subdomain; the server assigns one. The tunnel's display name comes from the target hostname, such as `localhost`.

### 4. Stop your tunnel

Press `Ctrl+C` in the agent terminal to disconnect.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| A required setting is missing | Supply a server-issued token; automatic registration is pending backend integration. |
| Connection or authentication fails | Confirm the server URL, server availability, and your agent token. |
| The public URL returns a 502 response | Confirm your local application is running and `--target` points to its correct address and port. |
| A download link does not work | Open the Releases page and check whether that platform's archive is available. |

## Install the command on PATH

After extracting your platform's archive, install the executable into a directory on your `PATH` to run it as `tunnexo` from any folder.

**macOS / Linux**

```sh
mkdir -p "$HOME/.local/bin"
chmod +x ./tunnexo
cp ./tunnexo "$HOME/.local/bin/tunnexo"
export PATH="$HOME/.local/bin:$PATH"
tunnexo --help
```

Add the `export PATH` line to your shell startup file (`~/.zshrc` or `~/.bashrc`) for future terminals.

**Windows**

Move `tunnexo.exe` into a permanent folder such as `%LOCALAPPDATA%\Tunnexo`, add that folder to your user `Path` through Windows Environment Variables, and open a new PowerShell terminal.

```powershell
tunnexo --help
tunnexo version
tunnexo agent --target http://localhost:4000
```

If using an optional `.env`, run from its folder. With environment-based authentication, run from any folder.

## Build and release

Requires Go 1.27.1 or newer. The GitHub repository and Go module remain `github.com/SharmaG-Dev/Portune-Agent`; the product and executable are Tunnexo.

```sh
go test ./...
go vet ./...
go build -o tunnexo .
bash scripts/build-release.sh
```

The release script builds macOS (ARM64/AMD64), Linux (ARM64/AMD64), and Windows (AMD64) packages in `dist/`, including the README and MIT license. It requires `zip` and `tar`. Upload the generated `tunnexo_*` archives to a GitHub Release to activate the download links above.

For Docker:

```sh
docker build -t tunnexo-agent .
docker run --rm tunnexo-agent --help
```

When running tunnels in Docker, supply configuration using `--env-file` and use a target address reachable from inside the container; `localhost` refers to the container itself.

## Production domain setup

The server returns the public tunnel URL; the agent displays that URL without rewriting it. To serve `https://<subdomain>.tunnexo.live`, configure the tunnel server's public domain, wildcard DNS for `*.tunnexo.live`, HTTPS certificates covering the wildcard, and proxy routing to the tunnel server. These settings belong to the server and DNS deployment.
